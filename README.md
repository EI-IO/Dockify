# Dockify · 一键变 Dock

> 给 Windows 11 任务栏做**两侧裁切 + 圆角**，一键把「开始按钮 + 程序图标 + 系统托盘」压成一条**居中的悬浮 Dock**。

> 给 Windows 11 任务栏做**两侧裁切 + 圆角**，并支持把「开始按钮 + 程序图标 + 系统托盘」压成一条**居中的悬浮 Dock**。
>
> A tiny tray app for Windows 11: rounds the taskbar corners, crops its two ends, and can turn the taskbar into a centered floating dock.
>
> **当前版本：v1.2** · 更新记录见 [CHANGELOG.md](CHANGELOG.md) · 已知限制见文末
>
> **程序由 DeepSeek 编写构建**（源码、注释、文档与自检均由 DeepSeek 完成）。
> **No installer, no runtime, no injection** — a single ~60 KB `.exe` built with the `csc.exe` that ships with Windows.

## 功能

- **两侧裁切 + 圆角**（默认模式）：任务栏不再贴屏幕左右边缘，四角变圆角，中间仍是系统原本的任务栏。
- **紧凑 Dock**：把任务栏重排成一条居中的圆角短条 —— 开始按钮、程序图标、系统托盘连成一排，长度随图标增减自动伸缩。
- **托盘弹出面板跟随**：`^` 隐藏图标面板跟着托盘一起平移（毫秒级、一步到位，不会"先弹错位置再跳一下"）。
- **自动隐藏兼容**：任务栏窗口本身从不移动，滑出/唤出与点击行为完全不受影响。
- **托盘常驻**：右键可开设置、切换模式、开关开机自启、恢复任务栏原样。
- **纯文本配置**：所有可调项都在一个带注释的 `.ini` 里，可直接手改。

## 快速开始

1. 下载 Release 里的 `Dockify-v1.2.zip`，解压到任意目录（例如 `D:\Tools\Dockify\`）。
2. **双击 `Dockify.exe`**（**不要在受限的终端 / 沙箱里启动**，见"常见问题"）。
3. 首次启动会自动生成配置文件并弹出设置窗口。
4. 托盘出现图标 → 右键可随时调整。

**想还原任务栏**：双击 `reset-taskbar.cmd`，或托盘右键 →「恢复任务栏原样」。

> 用过托盘里的「开机自动启动」的话注意：**自启项记的是当前 exe 的路径**。把程序挪到别处（或改用 install.cmd 安装）之前，建议先在托盘里取消勾选，免得自启到旧路径。

## 使用

### 托盘图标右键菜单

| 菜单项 | 说明 |
|---|---|
| 启用圆角裁切（可勾选） | 取消勾选 = 立刻把任务栏还原成原样 |
| 设置… | 打开设置窗口 |
| 恢复任务栏原样 | 等于 `--reset`（内容区、托盘、区域全部还原） |
| 立即重新裁切 | 手动重跑一轮（等你手动改过任务栏时用） |
| 模式 → 裁两端（整屏宽） | 整屏宽，只把两头裁圆 |
| 模式 → 紧凑 Dock（图标+托盘居中） | 图标 + 托盘压成一条居中的短条 |
| 开机自动启动 | 优先建**计划任务**（最高权限，开机即管理员、不弹 UAC）；无权限时退回 `HKCU\...\Run` 启动项 |
| 重新校准弹出面板 | 把"当前图标位置"记为弹窗跟随的新基准（觉得弹窗偏了、又不想开设置窗时用） |
| 以管理员身份重启… | 仅当前非管理员时出现：走 UAC 提权并自动接管（任务栏操作被系统拒绝时用） |
| 关于 / 退出 | 版本信息 / 退出并还原任务栏 |

### 命令行

```bat
Dockify.exe                 :: 常驻 + 托盘（首次运行会弹设置窗口并生成配置）
Dockify.exe --settings      :: 直接打开设置窗口
Dockify.exe --apply         :: 只套用一次就退出（退出码 0=成功 2=失败，便于脚本/计划任务）
Dockify.exe --diag          :: 跑一遍并写诊断报告
Dockify.exe --reset         :: 一键还原任务栏（内容区、托盘、区域全部还原）
```

- 前缀 `--` 与 `/` 等价、大小写不敏感；别名：`--reset`=`--restore`、`--settings`=`--config`、`--diag`=`--diagnose`。
- 诊断报告写到 `%APPDATA%\Dockify\diag.txt`；写不进去（受限进程常见）退到 `%TEMP%\Dockify-diag.txt`。
- 它是 GUI 子系统程序（winexe），`--diag` **不会在控制台打印**，请看上面的文件。
- 程序已在常驻时再运行一次不会起第二个实例，只会让已运行的实例弹出设置窗口 —— 脚本里请用 `--apply`。

## 设置项一览

> **所有尺寸类选项都是「占屏幕尺寸的浮点百分比」**（保存时最多三位小数，界面步进 0.05）。
> **横向项**按**显示器宽度**算，**纵向项**按**显示器高度**算 —— 换分辨率、换 DPI、换显示器都不用重调。
> 不在主界面上的项都在「**更多设置**」里：上/下边距、^面板左移、**整体偏移**、所有显示器都处理、数值随系统缩放、任务栏自动隐藏时也处理。

| 设置 | 单位 | 范围 | 说明 |
|---|---|---|---|
| 启用 | 勾选 | | 取消勾选立刻还原任务栏 |
| 模式 | 单选 | | `裁两端` / `紧凑 Dock` |
| **圆角圆度** | %（屏高） | 0 ~ 6 | 12px @1080p ≈ **1.11%** |
| **左裁切 / 右裁切** | %（屏宽） | 0 ~ 20 | 「裁两端」模式的两侧裁掉多少 |
| **短条留白** | %（屏宽） | 0 ~ 10 | 短条比内容每边多留的白；27px ≈ **1.4%** |
| **图标/托盘间距** | %（屏宽） | 0 ~ 5 | 程序图标区与系统托盘之间的空隙；16px ≈ **0.83%** |
| **内容长度微调** | %（屏宽） | 0 ~ 20 | 把内容区往窄了收（托盘会更往左靠）；20px ≈ **1.04%** |
| **左侧裁切微调** | %（屏宽） | −30 ~ 20 | **负值 = 往右多裁、贴近 Windows 图标**；−30px ≈ **−1.56%** |
| 上边距 / 下边距 | %（屏高） | 0 ~ 6 | 在「更多设置」里 |
| **面板动态跟随** | 勾选 | | `^` 展开面板 / 隐藏图标面板**随图标增减自动对齐**（默认开）。关掉则退回"只用固定微调"
| **预览动态跟随** | 勾选 | | **鼠标悬停程序图标时的预览缩略图**随图标增减自动对齐（默认开）
| ^面板微调 | %（屏宽） | −25 ~ 25 | 在动态跟随之上的残差微调；**正 = 往左**。你现在调的 7.58% ≈ 146px 就留着当残差
| 预览微调 | %（屏宽） | −25 ~ 25 | 悬停预览的残差微调；**正 = 往左**，一般不用动
| **整体偏移** | %（屏宽） | −25 ~ 25 | **手动左右挪整条 Dock**（正 = 往右，负 = 往左）；叠加在自动居中之上，**0 = 自动居中的几何中心**；出厂默认值是 **0.68%**（≈13px @1920，实测观感居中） |
| **视角重心补偿** | 勾选 | | 短条的**几何中心**与**视觉重心**本不重合；勾选后按 **1.32%** 屏宽再右移一点（**默认关闭**）。偏差因人因屏而异，先用尺子比一比再决定 |
| 所有显示器都处理 | 勾选 | | 副屏任务栏一起处理 |
| 数值随系统缩放 | 勾选 | | 内部常量是否跟随 DPI |
| 任务栏自动隐藏时也处理 | 勾选 | | 默认开 |

**换算方法**：`百分比 = 像素 ÷ 屏幕尺寸 × 100`
例：1080p（1920×1080）上想要 30px 的左侧裁切 → `30 ÷ 1920 × 100 = 1.56%`

## 配置文件

路径：`%APPDATA%\Dockify\settings.ini`（纯文本，UTF-8，带注释，可直接编辑）

```ini
# Dockify 设置（中文注释行以 # 开头，可直接手改）
# Mode: 0 = 只裁两端（出厂默认，最安全）, 2 = 紧凑 Dock（内容居中 + 贴合内容的圆角短条）
Enabled=1
MarginLeft=0.42          # 左裁切 %（显示器宽度）
MarginRight=0.42         # 右裁切 %（显示器宽度）
MarginTop=0              # 上边距 %（显示器高度）
MarginBottom=0           # 下边距 %（显示器高度）
Radius=1.11              # 圆角圆度 %（显示器高度）≈12px @1080p
AllMonitors=1
ScaleWithDpi=1
ApplyOnAutoHide=1
Mode=0
DockPadding=1.4          # 短条留白 %（显示器宽度）≈27px
ClusterGap=0.83          # 图标/托盘间距 % ≈16px
DockOffsetX=-1.56        # 左侧裁切微调 %（负 = 贴近 Windows 图标）≈-30px
DockWidthTrim=1.04       # 内容长度微调 %（往窄了收）≈20px
DockShiftX=0             # 整体偏移 %（正 = 往右，负 = 往左，0 = 自动居中）
VisualCenterComp=0       # 视角重心补偿：1 = 开启（再右移 1.32%），0 = 关闭（默认）
SavedTaskbarAl=-1        # 用户原本的任务栏对齐方式（-1 = 无需还原），程序内部使用
SettingsVersion=4        # 配置版本，用于一次性迁移，请勿手改
FlyoutOffsetX=7.58       # ^面板微调 %（正 = 往左），叠加在动态跟随之上
FlyoutFollow=1           # 面板动态跟随（随图标增减自动对齐）
PreviewFollow=1          # 预览动态跟随（悬停缩略图跟随图标）
PreviewOffsetX=0         # 预览微调 %（正 = 往左）
CalibIconShift=-2147483648  # 校准基准（程序内部，首次 Dock 成功后自动写入）
```

- **首次启动**：文件不存在时自动写入默认值（并弹出设置窗口）。
- **之后每次启动**：完全从文件读取，不用默认值覆盖。
- **老版本配置**：按 `SettingsVersion` 自动迁移（像素 → 百分比）。
- 万一写不进去，原因会记在 `%APPDATA%\Dockify\diag.txt` 的 `配置写入失败:` 一行。

## 构建

**不需要 Visual Studio，也不需要 .NET SDK** —— 用 Windows 自带的 `csc.exe` 即可。

```bat
:: 方式一：双击
build.cmd

:: 方式二：PowerShell
powershell -NoProfile -ExecutionPolicy Bypass -File build.ps1

:: 产物
dist\Dockify.exe
```

`build.ps1` 做这几件事：

1. 定位 `%WINDIR%\Microsoft.NET\Framework64\v4.0.30319\csc.exe`
2. 若 `build\app.ico` 不存在则现场生成（纯代码画图标，无外部素材）
3. 先删掉旧的 `dist\Dockify.exe`（避免编译失败却留下旧产物）
4. 编译 `src\Dockify.cs`，引用 `System.Windows.Forms` / `System.Drawing` / `UIAutomationClient` / `UIAutomationTypes` / `WindowsBase`

### 源码结构

单文件 C#，**C# 5 语法**（系统自带 csc 不支持更高版本，所以没有字符串插值 / `?.` / `nameof`）：

| 部分 | 作用 |
|---|---|

| `Program` | 单实例、托盘图标与菜单、命令行、自检与还原 |

## 工作原理（都是实测结论）

1. **任务栏是 Explorer 的顶层窗口**（主屏 `Shell_TrayWnd`、副屏 `Shell_SecondaryTrayWnd`）。
   用 `SetWindowRgn` + `CreateRoundRectRgn` 给它一个圆角矩形区域即可裁切 —— 窗口区域不影响布局，
   所以任务栏窗口本身**从不移动**，自动隐藏 / 唤出行为完全不受影响。

2. **任务栏画面由子窗口承载**：`Windows.UI.Composition.DesktopWindowContentBridge`（内容区）。
   改它的**宽度**会让 Windows 重排任务栏内容：程序图标组位置不变，而**系统托盘贴到内容区右端**。
   于是「内容区右端 = 图标右端 + 间距 + 托盘宽」就能让托盘紧贴图标，且**增删图标时自动伸缩**。

3. **可见的短条形状由内容区决定**，窗口区域只能"切"、不能"补"。
   所以**区域边界必须落在内容里侧**，两侧圆角才会显现（内容区右端要比托盘再宽一点点）。

4. **UI Automation 的图标矩形比可见图标宽一圈**（开始按钮有内边距）。
   「左侧裁切微调」就是在补偿这段差值（1080p @125% 实测约 47px），否则短条会离图标一段空隙。

5. **UI Automation 只在任务栏"唤出"时才有按钮**：自动隐藏滑出屏幕时返回空树。
   程序因此在任务栏不在屏幕内时**整轮跳过**（绝不用过期数据推算 —— 早期版本正是这样越推越偏）。

6. **平移内容区是危险的**：曾尝试"平移内容区让整组居中"，但宽度公式含 `-relX`，
   一左移宽度就跟着膨胀，撞上"整条任务栏宽"后 Windows 按整屏重排、短条报废。
   现在宽度**与位置完全解耦**，并设了硬上限（绝不允许等于整条任务栏宽）。

7. **托盘弹出面板**：`^` 隐藏图标面板（`TopLevelWindowForOverflowXamlIsland`）跟着托盘锚定，
   用 `SetWinEventHook(EVENT_OBJECT_SHOW / EVENT_OBJECT_LOCATIONCHANGE)` 在它出现的**毫秒级**摆好位置；
   网络 / 音量 / 电池 的快捷设置（`Xaml_WindowedPopupClass`）本身锚定正常，**不移动**。

8. **弹窗（悬停预览 / `^` 展开面板）为什么要"动态跟随"**：
   Explorer 给这些窗口算位置时，用的是**未加 Dock 的原始布局**，所以 Dock 一改变几何它们就错位。
   本项目实测到一条很干净的规律：**需要的偏移量 ≈ 图标组相对"自然居中位置"的位移**。
   未加 Dock 时程序图标组是屏幕居中的（自然左端 `= (任务栏宽 − 图标组宽) / 2`），
   加 Dock 后被平移了 `applied`，两者之差就是"Explorer 不知道的那段"：

   ```
   图标组位移 rowShift = (图标左端 + applied) − (任务栏宽 − 图标组宽) / 2
   弹窗需要往左挪的量 ≈ −rowShift        （图标增减时它会自己变，所以不需要写死百分比）
   ```

   证据：旧诊断里图标组 406..1232（宽 826），自然左端 = (1920−826)/2 = 547 → `rowShift = −141px`；
   而当时手工调出来能对齐的 `^面板左移` 是 7.58% × 1920 ≈ **146px** —— 两者几乎相等。
   实现上还留了一层**校准快照**：你点「确定」时若动过偏移，就把当时的 `rowShift` 记为新基准，
   于是"你调好的那一刻"分毫不差，之后图标增减才继续自动跟随。

## 悬停预览与弹出面板的对齐（实测结论）

Dock 靠"收窄并平移任务栏内容区"把图标和托盘搬成一条居中短条。Explorer 给弹出窗口定位时用的是
**未加 Dock 的原始布局**，所以这些窗口会跟着错位。实测与对策：

| 窗口 | 表现 | 处理 |
|---|---|---|
| `^` 展开面板 / 隐藏图标面板 | Explorer **自己锚定就是对的**；我们一补反而"二次移动"推歪 | **不动它**（`FlyoutFollow=0`、`FlyoutOffsetX=0`，这是默认值） |
| 鼠标悬停程序图标的**窗口预览** | 没有自己的窗口：它画在一个**全屏 XAML 岛**（`XamlExplorerHostIslandWindow`）里，偏位量正好等于内容区平移量（实测 144px） | **把这个岛也平移同样的量** —— 实测移动岛，岛里的预览 **1:1 跟着走**（岛左移 144px，预览中心 958 → 812，误差 ≤2px） |
| 网络/音量/电池（快捷设置） | 锚定正常 | **不移动**（按用户要求） |

另实测：**任务栏窗口本身推不动** —— `MoveWindow` 后 Explorer 会在几百毫秒内把它拽回原位，所以"移动任务栏窗口"这条路不可行。

两个开关都在「更多设置」：**面板动态跟随** / **预览动态跟随**（预览跟随默认开；关掉会把岛放回原位）。

## 已知限制

- **圆角是硬边**：窗口区域是 1 位掩码，无法抗锯齿。想要真正平滑的圆角需要注入 Explorer（Windhawk 等方案）。
- **内容区收得太窄时 Windows 会开始隐藏图标**（它的保护机制），不是程序隐藏的。
- **程序会临时改写系统的任务栏对齐设置**：紧凑 Dock 要求任务栏居中，所以启动时若检测到你是"居左"，会把 `HKCU\Software\Microsoft\Windows\CurrentVersion\Explorer\Advanced\TaskbarAl` 临时改成居中（原值记在配置里），退出或 `--reset` 时还原。**若进程被强杀（任务管理器结束、断电），下次启动会继续使用它会自行校正；但如果你此后再也不运行本程序，需要手动改回"居左"。**
- **必须从正常桌面启动**：若从受限终端 / 沙箱里被拉起，进程拿不到干净上下文，会看不到任务栏
  （诊断里表现为 `任务栏: 找到 0 个`）。程序会尝试**请资源管理器代为重启一次**；
  仍不行就**以管理员身份运行**，或重启一次资源管理器。
- **Explorer 更新可能改变几何**：内容区子窗口类名、按钮内边距等若变化，需按"工作原理"第 4 条重新校准。
- 仅主屏 + 副屏任务栏做了处理；竖排任务栏未测试。

## 权限与开机自启

任务栏是 **Explorer** 的窗口。普通权限下本程序**通常**能正常裁切，但有些系统配置会拒绝 `SetWindowRgn`
（例如 Explorer 以更高的完整性级别运行，或程序本身是从受限终端/沙箱里被拉起来的）——此时状态栏会显示
「**被拒绝访问**」，程序自己也看不到任务栏（诊断里是 `任务栏: 找到 0 个`）。

- **一键提权**：托盘右键 →「**以管理员身份重启…**」（只在当前非管理员时出现）。走标准 UAC 提权，
  提权后的实例会自动接管任务栏。
- **开机自启**：托盘勾选「开机自动启动」时，程序**优先创建一个计划任务**：
  ```
  schtasks /Create /TN Dockify /TR "\"<exe 路径>\"" /SC ONLOGON /RL HIGHEST /DELAY 0000:10 /F
  ```
  也就是「登录后延迟 10 秒、**以最高权限**启动」—— 开机后就是管理员身份静默运行，**不会再弹 UAC**。
  若当前没有管理员权限，建不了这种任务，会自动退回经典的 `HKCU\...\Run` 启动项（以普通权限启动）。
- 取消勾选会**同时清掉**计划任务和 Run 键，不会残留。
- 手动确认：`schtasks /Query /TN Dockify`（存在即已启用计划任务）。
## 常见问题

**Q：短条出来了，但左边空一块？**
A：那是"开始按钮矩形"与"可见图标"的差值。把「左侧裁切微调」往负方向调，直到短条贴住图标
（1080p @125% 参考值 `-1.56%`；调过头会切进图标，回调一点即可）。

**Q：短条看着没居中？**
A：先确认「更多设置 → 视角重心补偿」**没有**勾上（勾了会整体右移 1.32%）。
若仍觉得偏，用「更多设置 → 整体偏移」手动挪：
1080p 上偏 58px 就填 `-3%`（`58 ÷ 1920 × 100`）。这一项**永远生效**，不依赖自动居中。

**Q：状态栏显示"未找到任务栏"？**
A：进程上下文受限。退出后**从文件资源管理器双击**启动；或右键 →「以管理员身份运行」；
或先重启一次「Windows 资源管理器」。

**Q：任务栏一直闪 / 在两个模式间跳？**
A：早期版本的 bug（"居左"误判 + 失败无冷却），已修复。若仍出现，看一眼设置窗口状态行的说明。

**Q：想彻底卸载？**
A：`--reset` 还原任务栏 → 删除程序目录与 `%APPDATA%\Dockify\` → 删除开机自启项即可。

## 权限、启动与「预览对正」的最终取舍（2026-10-08 实测定稿）

### 必须以管理员运行

任务栏是资源管理器（explorer.exe）的窗口，普通权限进程改它会被系统拒绝（`SetWindowRgn` 无效）。
所以程序在启动时就检查权限：

- **非管理员启动** → 自动以管理员重启自己（`TryRelaunchElevated()`，`Verb=runas`）。
  本机 UAC 是"不提示直接提权"（`ConsentPromptBehaviorAdmin=0`），所以双击即静默变管理员。
- 用户在 UAC 上点"否" → **程序直接退出**，不常驻、不假装在工作。

### 托盘新增项

- **重启 Dockify（重新加载设置）**：启动时只读一次 `settings.ini`，手改配置后用这项重载最省事。
  本进程已是管理员 → 子进程直接继承管理员令牌，不会再弹 UAC。
- **测量弹窗/预览对正（写 align.txt）**：把预览岛与各类弹窗的实际坐标写进 `%APPDATA%\Dockify\align.txt`，排障用。

### 悬停预览为什么不能"既居中又对正"（重要）

实测结论：悬停窗口预览在本系统上**没有可移动的窗口**（不是 `XamlExplorerHostIslandWindow`，
移动 `TopLevelWindowForOverflowXamlIsland` 也完全不动它），它是 Explorer 按**"图标没被 Dock 平移过"的位置**画的。

而紧凑 Dock 要**居中**，就必须把图标组左推约 156px（给右侧托盘腾位置 —— 托盘必须贴在图标右边，这一点绕不过去）。
于是预览必然偏右 156px：**推多少就偏多少**。

| 方案 | 短条（常驻可见） | 悬停预览 |
|---|---|---|
| **A 居中优先（本项目采用）** | 完美居中 | 偏右 ≈160px |
| B 预览优先（不推图标组） | 偏右 ≈150px | 完美对正 |
| C 折中（平移减半） | 各偏 ≈80px | 各偏 ≈80px |

采用 A：短条是常驻可见的，预览只在悬停瞬间出现。
配置里 `PreviewFollow=0` 表示**不去挪那个 XAML 岛**（本机挪了也没用，反而可能在别的 XAML 界面出现时误移），
`FlyoutFollow=1` 保留 `^` 隐藏图标面板的对正补偿（实测偏差仅 26px）。
